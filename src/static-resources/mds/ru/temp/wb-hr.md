## Предполагаемые вопросы и ответы

### 1. Расскажите подробнее про ваш опыт с CODELESS. Что это за продукт?

**Ответ:**
CODELESS — это CMS система, альтернативный способ создания frontend приложений. Платформа с набором визуальных инструментов и собственным языком программирования для разработчиков.

Ключевые компоненты платформы:

- **Редактор верстки** — визуальный конструктор для построения UI
- **Редактор кода и типов** — code editor для написания бизнес-логики на собственном языке (псевдокод, похожий на JavaScript), который интерпретируется в JavaScript
- **Интеграция с backend API** — подключение к любым REST API
- **Локализация** — мультиязычность из коробки
- **State manager** — управление состоянием приложения
- **Система компонентов** — переиспользуемые UI блоки
- **Система модулей** — подключение внешних модулей через npm/Nexus

На CODELESS создавались enterprise приложения для банковского сектора — модули счетов, выписок, платежных поручений, управления сотрудниками для ВТБ, Газпром Банка, Открытия.

Архитектура: SDUI-подход — конфигурация UI и логики хранилась на сервере (RavenDB), интерпретировалась и рендерилась динамически на клиенте.

### 2. Какие конкретно вы разрабатывали редакторы кода?

**Ответ:**
Я разрабатывал редактор выражений и типов для CODELESS с уникальной DOM-архитектурой — каждый элемент кода это отдельный DOM-элемент, а не текстовое представление.

Ключевые особенности:

- **Real-time валидация**: синтаксические и семантические ошибки подсвечиваются моментально
- **Умное автодополнение**: контекстные подсказки с типизацией
- **Встроенный дебаггер**: пошаговое логирование выполнения
- **Performance**: рендеринг только видимых элементов, кэширование форматирования
- **Типизация**: полная TypeScript типизация, определение типов, проверка совместимости
- **UX**: масштабирование шрифта, адаптивность, полная поддержка Copy/Cut/Paste

Технически это был AST-based редактор с собственным парсером и интерпретатором.

### 3. Расскажите про ваш опыт работы с AI/ML моделями

**Ответ:**
В проекте Smart Cart Bot я делал полный цикл работы с LLM моделью:

**Fine-tuning процесс:**

- Выбрал Mistral 7B как базовую модель
- Сгенерировал датасет из 1500+ обучающих записей через GPT-4

**Интеграция:**

- Реализовал очередность запросов к модели
- Настроил кэширование для повторных запросов
- Оптимизировал латентность и throughput

**Результат:**
Модель парсит пользовательские сообщения типа "молоко 2 литра, хлеб 3 буханки" в структурированный JSON с распознаванием количества, единиц измерения и категорий товаров.

Помимо этого, использовал GPT-4 API для генерации обучающих данных, экспериментировал с разными параметрами inference (temperature, top_p).

**Ответ:**
В CODELESS активно применялся SDUI-подход:

**Как это работало:**

**Преимущества подхода:**

### 8. Какой у вас опыт с WebSocket?

**Ответ:**
Прямой опыт с WebSocket у меня через proxy-конфигурацию в CODELESS — я разрабатывал систему настройки прокси для каждого "пода", которая поддерживала как HTTP, так и WS соединения с перенаправлением, сменой заголовков, правилами замены путей.

Также активно работал с Server-Sent Events (SSE) — это однонаправленная альтернатива WebSocket:

- В CODELESS: real-time обновления статуса сборки проектов
- В Smart Cart Bot: моментальное обновление статуса сборки корзин и смены города

**Понимание:**
Разница между WebSocket (bidirectional, full-duplex) и SSE (server-to-client). Использую SSE когда нужен только server-to-client stream, WebSocket — для bidirectional communication (чаты, collaborative editing).

Готов работать с WebSocket для real-time features в AI-конструкторе интерфейсов.
