# Промт: Пересборка резюме

> **Приложи к этому промту 4 файла:**
> 1. `resume.md` — текущая версия резюме
> 2. `jtc.md` — детальное описание опыта в JTC
> 3. `recifra.md` — детальное описание опыта в Рецифра
> 4. `smart-cart.md` — детальное описание личного проекта Smart Cart Bot

---

## Задача

Ты — эксперт по составлению резюме для IT-специалистов с 15-летним опытом работы HR-консультантом в Big Tech и ведущих продуктовых компаниях. Твоя задача — **пересобрать резюме** Senior Frontend/Fullstack Developer так, чтобы максимально повысить шансы на приглашение на собеседование.

Целевая аудитория: HR-менеджеры и технические лиды, которые тратят 10–30 секунд на первичный скрининг резюме.

---

## Входные данные

- **resume.md** — текущая версия резюме (базовая структура и контент)
- **jtc.md** — расширенная информация по опыту в JTC (ООО «ДжейТи Консалтинг»)
- **recifra.md** — расширенная информация по опыту в Рецифра
- **smart-cart.md** — расширенная информация по личному проекту Smart Cart Bot

---

## Целевой профиль

- **Позиция:** Senior Frontend Developer / Senior Fullstack Developer с уклоном в AI/ML
- **Формат работы:** удалённая работа, гибридный формат, готов к релокации
- **Язык резюме:** русский
- **Зарплатные ожидания:** НЕ указывать

---

## Принципы сильного резюме

### 1. Результат > процесс

Каждый пункт опыта должен отвечать на вопрос "какой результат был достигнут?", а не "чем я занимался". Используй формулу:

```
[Глагол действия] + [что сделал] + [результат/влияние на бизнес]
```

**Плохо:** «Участвовал в проектировании и реализации миграции с файловой системы на RavenDB»
**Хорошо:** «Спроектировал и реализовал миграцию хранилища данных с файловой системы на RavenDB, устранив проблемы с производительностью при росте проектов и обеспечив горизонтальное масштабирование»

### 2. Конкретика и масштаб

Где возможно — добавляй масштаб: количество пользователей, размер команды, число проектов, процент ускорения, объём данных. Если точных цифр нет — используй порядковые оценки ("десятки модулей", "крупные банки с миллионами клиентов").

### 3. Сильные глаголы действия

Используй: спроектировал, реализовал, внедрил, оптимизировал, автоматизировал, разработал с нуля, повысил, сократил, масштабировал, интегрировал, возглавил.

Избегай: участвовал, помогал, работал над, занимался, был ответственным.

### 4. Ключевые слова для ATS

Резюме должно проходить через ATS-системы. Убедись, что ключевые технологии и навыки присутствуют в тексте в явном виде (React, TypeScript, Node.js, AI/ML, и т.д.).

### 5. Визуальная иерархия

- Самая важная информация — в первых строках каждого блока
- Самый свежий и релевантный опыт — подробнее, старый — компактнее
- Не более 4–5 пунктов на позицию в основном резюме (детали — на отдельных страницах)

## Обязательная структура выходного резюме

### Шапка
- Имя, должность
- Контакты: Telegram, GitHub, email
- Формат: лаконичный, без лишнего

### Профессиональное резюме (Summary)
- 3–4 предложения, ёмко описывающие профиль
- Должно чётко передавать: уровень (Senior), стек (React, TypeScript, Node.js), особенность (AI/ML), опыт (9+ лет), тип проектов (enterprise)
- Это самый важный блок — HR читает его первым и решает, читать ли дальше

### Ключевые навыки
- Группировка по категориям (Frontend, Backend, AI/ML, Инструменты)
- Только актуальные технологии, без устаревших (jQuery, Backbone — не выносить в навыки)
- Формат: теги/бейджи через бэктики

### Опыт работы
- Обратная хронология (от нового к старому)
- Каждая позиция: должность, компания, город, период
- Ссылка "Подробнее →" на детальную страницу (сохранить существующие URL: `/jtc`, `/recifra`, `/smart-cart`)
- Пункты достижений — по формуле "глагол + что + результат"
- Технологии в конце каждой позиции

**Важно по JTC:**
- У кандидата было 2 периода в JTC (Frontend Developer → Senior Frontend Developer). Подай это как рост внутри компании
- Выдели ключевые достижения Senior-периода ярче, а Junior-период — компактнее
- Подчеркни: создание архитектурных решений, миграция системы, внедрение инноваций

**Важно по Рецифра:**
- Это ранний опыт — подать компактно, но не пренебрежительно
- Выделить масштаб: государственные проекты, работа с госзаказчиками, мобильное приложение Госуслуги

### Личные проекты
- Smart Cart Bot — подать как демонстрацию AI/ML навыков
- Акцент на: дообучение модели, микросервисная архитектура, реальный продукт с пользователями
- Ссылки на Telegram-бот и GitHub

### Образование
- Компактно: ВУЗ, специальность, период
- Стипендия губернатора — оставить как достижение

### Дополнительная информация
- Формат работы: удалённая / гибрид / готов к релокации
- Интересы: кратко
- **НЕ указывать** зарплатные ожидания
- **НЕ указывать** статус поиска ("активно ищу") — это выглядит нуждающимся

## Чего НЕ делать

1. **Не раздувай** — резюме должно быть сканируемым за 30 секунд. Детали — на отдельных страницах
2. **Не используй** канцелярит и клише ("динамично развивающаяся компания", "командный игрок")
3. **Не пиши** от первого лица ("Я разработал") — используй безличные конструкции или глагол без местоимения ("Разработал")
4. **Не указывай** причины увольнения
5. **Не добавляй** софт-скиллы отдельным блоком — они должны быть видны через достижения
6. **Не ставь** фото, дату рождения, семейное положение
7. **Не придумывай** факты — используй только информацию из приложенных файлов
8. **Не теряй** ссылки на подробные страницы (`/jtc`, `/recifra`, `/smart-cart`)

## Формат вывода

- Markdown (`.md`)
- Резюме будет опубликовано на сайте и сверстано в PDF — оно должно выглядеть профессионально и привычно для HR
- Используй горизонтальные разделители (`---`) между секциями
- Используй бэктики для технологий
- Используй эмодзи только в контактах (📱💻✉️) — в остальном тексте не использовать
- Общий объём: сопоставим с текущим (120–180 строк MD), не больше
